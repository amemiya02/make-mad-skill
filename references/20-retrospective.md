# 20 经验库与自进化协议

本文件分三部分：用户的红线、每个项目的复盘账本、可复用的工作流改进。

- **每个新项目开工前**：先读“红线速查”和“账本”。
- **每个项目交付时**：按“自进化协议”把新教训写回 skill。

## 1. 自进化协议（G7 交付时必做）
1. **收集原话**：把用户每一轮的审片意见按原话记进项目的 `reviews/review.md`，带版本号和日期。
2. **分类**：每条意见归入一类：
   - 叙事/结构
   - 镜头衔接
   - 转场
   - 特效
   - 文字/歌词
   - 声音
   - 选曲
   - 交付/工程
   - 协作方式
3. **找根因**：对每条意见找可验证的根因，不写“下次更认真”。例：
   - 衔接差 → 节拍网格测错了（librosa 测出 115 BPM，实际是 85.8 BPM）。
   - 顺序不合理 → 没按原作自带的交叉剪辑顺序排。
4. **落成规则**：把根因写成可执行的规则或检查，放进对应的 reference 文件：
   - 02 音乐
   - 04 剪辑
   - 05 转场
   - 07 声音字幕
   - 09 质量门
   - 14 精修
   - 17/18 顶级 MAD 思路
   - 19 后端

   能用脚本检查的，写进 `scripts/fxkit/`，并在其 README 登记。
5. **记账**：在下面的账本加一行，写清日期、项目、意见、根因、规则、落在哪个文件、证据（数字、帧图或日志路径）。
6. **红线升级**：同一类意见在两个版本里重复出现，就升级进“红线速查”。
7. **诚实**：账本只写测到和看到的。没有实际观看或聆听的，不写成“看过”或“听过”。

## 2. 红线速查（来自多轮真人审片）

### 叙事
- 一句话能说清作品讲什么。
- 每个镜头在上下文里读得懂。不要：1 秒的无解释特写、空景或只有树叶的镜头、远处看不清的小人。
- 段落之间要有因果。例：修行段的入口用视线接力，人物抬眼 → 墙上的剑 → 远方练剑的人。

### 衔接
- 先找原作里的连续段落，按原作顺序压缩。不要从各季、各地各抽一秒拼起来。
- 可用的衔接手法：
  - 同主体、同构图、换背景（表示时间流逝）。
  - 部位或动作阶段接力。
  - 色光接力。
- 快切之后要落在一个稳定镜头上，约一小节。

### 节拍
- 切点要落在**正确的**拍点和小节线上。先用 Beat This! 交叉校验拍号。
- 不追每一个起音。

### 转场
- 默认硬切。
- 溶解只用于两种情况：亮度相近且形状对齐的两个镜头之间，或全片统一的回忆语言。
- 白场只用原作自带的。

### 特效
- 不要外加：数字抖动、推拉脉冲、白闪帧、抠图描边辉光、镜头光晕、故障转场、无动机的推镜。
- 允许：原作自带的光；光敏安全处理（tmix）；有理由且幅度 ≤4% 的慢推。

### 遮幅
- 不要来回切换。

### 文字
- 剧情向要有完整的歌词字幕（日文 + 中文），一句一屏。
- 台词和歌词用同一种字体。
- 在任何背景上都要读得清：普通镜头用暗晕，高亮镜头在切点处换成深色字。
- 不做标题卡，不做冷开场（做的是 MAD，不是 MV）。

### 声音
- 台词必须去掉原片的配乐和环境声。
- 只在台词说话时压低音乐，句与句之间回升，不要整段压到底。
- 逐句测量，台词比音乐高 8–10 dB。

### 选曲
- 用户锁定曲目后不擅自换。
- 要换曲，先给候选和理由，等用户试听后决定（我们听不到）。

### 交付
- 码率中等，约 3.5–8 Mbps。
- 附可编辑的 `.ass` 字幕和 `.otio` 时间线。
- 只保留最终版。历史版本移到废纸篓，不直接永久删除。

## 4. 工作流改进（下个项目直接照做）

### G1：先研究再剪
- 选 20–40 部与目标风格最接近的顶尖 MAD。
- 用 `scripts/corpus/` 下载，用 `analyze_mad.py` 拆解。
- 让子代理按 `templates/mad-study-brief.md` 写笔记，再把结论归纳进 18 号文件。
- 已有 42 部的笔记在 `references/corpus/`，先读其中的 `index.csv`。

### G1：音乐
- 用 Beat This!（`openadobe ai run beats`）测拍号和小节线。
- 与 librosa 结果不一致时，以小节线为准。
- 歌词用两个来源核对行数。行数少不一定是缺，也可能歌词本身就稀疏。
- 用 `lrc_align.py` 把歌词吸附到人声片段。

### G2：素材索引
- 对每集的 480p 代理跑镜头检测。
- 用 `smeboard.py` 为每个镜头出首/中/尾三帧审片板。
- 在审片板上找三样东西：
  - 原作的连续段落：修行、战斗、离别。
  - 原作自带的交叉剪辑顺序。后一集常会重放前一集的场面，并插入回忆或幻象。
  - 可以做匹配剪辑的镜头对：同构图、同姿势、换背景。

### G3：原型
- 关键段（修行、死亡、结尾）先单独渲染。
- 依次检查：
  - 首/中/尾帧审片板（`protoboard.py`）。
  - `guard_spec`（杂帧）。
  - `redline`（闪烁）。
- 与旧版做 A/B 对比，修完再铺全片。

### G5/G6：精修
- 每个切点核对落在哪一拍。
- 每句台词测量它比音乐高多少 dB。
- 每行字幕对照背景亮度检查可读性（`textcheck`，切点处换墨色）。
- 源素材每秒闪烁超过 3 次时，用 tmix 抑制。

### 效率
- 镜头渲染按内容哈希缓存，只重渲改动过的镜头。
- 只改文字用 `--relayer`，只改混音用 `--audio-only`。
- 机器负载高时，开后台任务并等完成通知，不要轮询。

### 交付
- 交付物：成片、无字版、`.ass`、`.otio`、分轨、README（含 SHA256 和剩余限制）。
- 历史版本移进废纸篓。
- skill 的改动推送到远端仓库。
