# 精修：低级错误红线、逐秒打磨与FFmpeg特效工具链

本文件来自一次真实返工：第一版成片“结构成立”，但被指出 **人声丢失、几帧闪镜头、整片没有特效**。结构正确只是及格线；观众首先感到的是细节。下面的红线必须在任何粗剪审片之前自动+人工检查，逐秒打磨清单在精剪阶段逐镜头填写。

## 一、低级错误红线（任何一条命中＝不得交付）

| 红线 | 真实成因 | 检查方法 | 修复 |
|---|---|---|---|
| **闪帧/杂帧**：镜头开头或结尾混入1–4帧别的镜头 | 320px+阈值场景检测的边界不精确；对拍时把入点推到“下限”；溶解手柄向前取帧越过真实切点 | `scripts/fxkit/cutguard.py edl.csv`：对每个镜头源区间按原生帧率逐帧比较（像素差绝对值+相对局部中位数+直方图），报告区间内硬切；对每处报警看“切点前后4帧”对照图 | 入点/出点移到切点之后/之前；**溶解手柄用首帧冻结(tpad clone)而不是向前取源** |
| **歌声被压/丢失** | 为台词把整首歌压低6–9 dB，压到了演唱 | 用Demucs分离 `vocals.wav`，算无人声区间；成片与原曲在人声频段(300–3400 Hz)逐0.5 s比较 | 台词只放进无人声区间；只压低“伴奏”（无人声处即整曲）；有歌声处的台词改为**仅字幕**或手写字幕 |
| **口型错位** | 画面跳过一段源时间，但台词按连续源时间铺放 | 对每段台词计算其所在镜头的 song↔source 偏移，偏移不同就拆分台词 | 把台词按镜头拆成多段，分别对齐各自镜头；删去跨断点的半句 |
| **台词掐字/漏字** | 用字幕时间码直接当音频边界 | 在剧集音轨上做能量分段，取完整语音段 | 以语音段为准留0.05–0.1 s余量与淡入淡出 |
| **无意义的超短镜头** | 对拍把镜头切得只剩几帧 | 统计 <12帧(0.5 s) 的镜头并逐一说明理由 | 除设计好的闪切（雷光、冲击）外合并或延长 |
| **推拉越界拖影** | 焦点偏离中心+放大不足，采样窗超出源画面，边缘像素被拉伸 | 抽查推拉镜头首尾帧四边 | 采样窗中心钳制在 `[W/(2Z), W−W/(2Z)]`；震屏/旋转需更大安全余量 |
| **辉光/滤色偏色（洋红）** | `blend=screen` 在 YUV 上运算 | 对日落/火焰等高饱和镜头做前后对比 | 混合前 `format=gbrp` |
| **冲击方向反了/滤镜报错** | 表达式拼接 `W/2/Z*(1+k…)` 少括号，变成缩小，严重时采样窗大于画面导致 EINVAL | 渲染首帧与第20帧比较取景大小 | 整个缩放表达式外层加括号 |
| **闪烁超限** | 雷光等源本身频闪+剪点亮度突变 | 逐帧亮度差≥10%满幅且方向相反成对，任意1 s窗口计数 | 缩短/裁掉频闪段；≥3次/秒必须处理（W3C判据涉及面积和颜色，计数只是下限检查） |
| **烧录文字/台标** | OP/ED、片内字幕卡、战斗中的日文字卡 | 入选镜头逐帧条图（≥4 fps），片头片尾区间直接排除 | 换镜头或换区间，不裁不糊 |
| **成片过重/渲染太慢** | 24 Mbps 母版级编码，4:30 成片近 900 MB，用户认为没必要 | ffprobe 码率与文件大小 | 交付默认中等偏轻：拼接 CRF21 + `-maxrate 8M -bufsize 16M` + preset veryfast（≈250–300 MB）；中间镜头 CRF14 veryfast；需要母版时再单独出 |
| **码率爆炸** | 时域颗粒(noise allf=t)几乎不可压缩；CRF14+颗粒实测 1080p 75 Mbps、4.5分钟2.5 GB | ffprobe 看 bit_rate；>30 Mbps 即异常 | 颗粒 alls≤6，日常段2–3；最终 CRF16 + `-maxrate 24M -bufsize 48M` + aq-mode=3；mux 时只映射 `0:v:0`/`1:a:0` 并 `-dn` 去掉数据轨 |
| **无动机推镜（"总在由远及近拉近"）** | 给每个镜头默认加 1.0→1.1 推近当作"有动效"；本例 104 个镜头里 88 个在推 | 统计带 z0/z1 变化的镜头比例；>30% 即警报 | **默认锁定机位**；只在有叙事理由的镜头运镜（光亮起、眼睛睁开、烛火将熄、跟随余烬上摇、重燃时拉开），幅度 ≤1.06；冲击类 settle/punch/shake 属于对画面内动作的反应，可保留 |
| **遮幅与全幅来回切换** | 用遮幅表示回忆，但回忆与现实交替剪，遮幅一会儿有一会儿无 | 看遮幅开关次数 | 回忆只用调色区分；遮幅要么整段统一，要么不用 |
| **"设计的"闪切被当成杂帧** | 0.3–0.5 s 插入别的人物/闪电频闪 | 统计 <0.6 s 的镜头；逐帧看是否跨源切点 | 最短 0.6 s（同一动作内的冲击切除外）；频闪闪电整段删除 |
| **无意义空镜/填充镜** | 为了填时长插一张夕阳/风景 | 每个镜头写“它在这里说了什么” | 换成推进人物关系或情节的镜头 |
| **同角色段落地点乱跳** | 按"好看"挑镜头，不按时间/地点组织 | 把段落镜头的地点/时间/动作方向列成表 | 组织成一条单向进程（白天→黄昏→雪→夜→决战），切在挥剑动作上（cut on action） |
| **台词太少** | 歌曲人声几乎连续，没有可放台词的空隙 | 用分离人声算 ≥0.8 s 的无人声区间 | 设计台词空间：**冷开场**（歌前 20–40 s 纯台词序章，交代人物线）+ 间奏/器乐段/尾奏放满台词；绝不压在演唱上 |
| **台词带原片BGM** | 直接从剧集音轨截取 | 看台词片段的伴奏能量/频谱 | 见 `15-dialogue-isolation.md`：RoFormer 类人声分离 + 降噪 + 门限，所有台词一律清洗 |
| **歌词只做了几句** | 只给"锚点句"上字幕 | 歌词表行数 vs 人声乐句数 | 用了歌词就全曲每句都上，强制对齐（`lyric_align.py`）；歌词文本由用户/授权来源提供，agent 不复述整首受版权保护的歌词 |
| **书法/手写体字幕难看** | 为"风格化"用行楷等装饰字体 | 截图给人看 | 全片统一一套克制字体（明朝/宋体 + 柔和阴影），位置固定在下方安全区 |
| **字幕/歌词不可读** | 白字落在高调画面（白色梦境、强光、雪地）上；或暗色字落回暗镜头 | `scripts/fxkit/textcheck.py picture-clean.mp4 build.py`：在无字幕成片上取每条文字框下的亮度，白字背景均值>0.6或亮部>25%、墨字背景<0.35 即报 | 按时间区间切换为“墨色字+白晕”(`dark=([(t_on,t_off)],xf)`，在切点处0.1 s交叉)；遮幅镜头把对白字幕放进黑边内（1080p遮幅132 px，字幕 y≈972） |
| **高调源被二次提亮成白板** | 源本身接近全白（神域/光芒），又套高调look+辉光 | 全片条图里连续>1 s近白画面；对照源帧 | 对高调源反向压中高光（curves 0.7→0.55、0.9→0.8）+轻暗角，去掉辉光；需要保留光条的片头另设 soft 预设 |
| **图层沿用旧文件** | 歌词/光层按“文件存在即复用”，改了字幕仍合成旧 gfx | 图层旁存规格hash文件，构建时比对 | `layers.stale()/stamp()`：按元素参数+文字+layers.py 源码hash 判定；镜头缓存只hash逐镜头渲染代码（`_shot_src()`），改拼接参数不必全片重渲 |
| **白闪叠加** | 预合成自带定格白闪+恢复白闪，镜头层又叠 flash/head_fade，1.5 s 内三次白场（redline flash_windows≥3） | `redline` 闪烁窗口；对预合成逐帧算亮度曲线 | 每个英雄镜头只留一次白闪：`freeze_pop` 设 `resume_flash=0`、`flash≤0.45`；预合成内已有的闪不要在镜头层重复；段落白场渐变 ≤6 帧 |
| **光状态不连续** | 预合成里灯已点亮（神光），下一镜头又从未点燃的暗灯开始 → 亮-暗-亮 | 看相邻镜头首尾帧 | 下一镜头从“点燃那一帧”开始；源区间不够就微调速度(0.97)而不是跨切点 |
| **高调源+辉光=洗白** | 源本身是高调蓝白光的特写，再叠 glow 与抬 gamma 的调色 → 脸被洗白 3 秒，字幕也不可读 | 条图上看连续几秒的“雾面”；textcheck | 该镜头去掉 glow，`grade_extra='eq=gamma=0.84:contrast=1.12'` 压回 |
| **半明半暗背景上的白字** | 字幕一半压在深色墙、一半压在白衣上，白字和墨字都不全可读 | textcheck 的 bright_frac≈阈值 | `Caption(..., plate=0.6)`：字后加柔边暗底（羽化椭圆），不改字体/位置 |
| **切点守卫自己偏一帧** | `cutguard` 以“解码起点”推算切点时间，而精确 `-ss` 返回的是第一帧 pts≥入点 → 切点估计最多早一帧；守卫又在尾部扣掉半帧 → 镜头尾部紧贴源切点的 1 帧杂帧（v8：0.27 s 的眼神特写尾帧、过肩摔镜头尾帧）漏检 | 守卫用源帧网格：`g0=ceil(src·fps−0.05)/fps`（mkv 时间戳按毫秒取整），镜头含帧 `g0…g0+(n−1)/fps`；切点 c 落在 `(g0+½帧, 末帧+½帧)` 即报；`redline` 的 stray 嫌疑点**逐个**出前后 4 帧条图看 | 入点前移一帧或出点前移，让切点落在末帧之后 ≥1 帧；短于 0.5 s 的镜头首尾各留 ≥1 帧余量 |
| **把源本身的效果当成我们加的（或反之）** | 神域白光、雷光、全白回忆、源内辉光，和我们叠加的 glow/tmix 混在一起，审片时分不清 | 对每个“像特效”的镜头把**原始源帧**并排出图对照（`candrows`） | 源自带的保留；我们叠加的：glow 只给真实火焰/烛光且 ≤0.22，重影/闪白/抖动一律删除；`tmix` 帧混合只在源本身频闪（redline flash_windows≥3）时作为光敏安全修复保留——v8 删掉它后片头眨眼光立刻变成 4 次/秒频闪 |
| **渲染超时被杀/太慢** | 基础渲染器 `-threads 2` 逐镜头medium编码；缓存键覆盖整份源码导致改一行拼接参数就全片重渲；带字幕版和无字幕版各拼一遍 | 预估：帧数÷实测fps；看 load average 与空闲内存 | 线程放开、并行镜头、缓存键只覆盖逐镜头代码、先960×540预览；图层渲染与镜头渲染并行；**一次拼接 split 出带字幕/无字幕两路**；终编码 preset medium + 码率上限；成片后的 finalize/QA/条图并行；Claude Code 后台命令默认 30 分钟被杀——全片渲染显式给最长 timeout，并把“全部镜头→图层→拼接→混音”写成可重入脚本（缓存命中即跳过），被杀后直接重跑 |

## 二、逐秒打磨：每个镜头都要回答的问题

在构建脚本或 `effect-plan.csv` 里，每个镜头必须有明确决定（“不做”也要写理由）：

1. **调色**：所属段落的look（例：现在＝暖金；回忆/未来日记＝去饱和冷色+保留红色+抬黑+遮幅；梦境＝高调；黎明＝金色）。叙事上不同的时间线必须一眼可分。
2. **运动（镜头策略）**：**默认不加数码推拉**——原画自带的运镜就是运镜。人工推/拉/漂移只给“有理由”的少数镜头（≈5–10%）：揭示（拉出交代空间）、凝视（极慢推向眼睛/信物，≤1.05）、段落收尾的呼吸。在构建脚本里用一张 `MOVES = {id: dict(z0,z1,…)}` 白名单集中声明，其余镜头的运动键一律剥离——不要逐镜头随手写 z0/z1（v6 有 88/104 个镜头带推近，用户直接指出“莫名其妙的由远及近”）。冲击类(settle/punch/shake)只放在画面内真实的打击/落地顶点上。
3. **入/出转场**（v8 修订，见 17-top-mad-craft.md）：**硬切 ≥85–90%**。段落入口靠选镜与切点（cut on action、顺着原作光效切、匹配切），不靠加料。软转场只有：回忆/时间流逝的匹配溶解(0.5–1.5 s，色/光/形匹配)、段落收束与片头片尾的淡黑。**主动白闪整片 ≤1 次**（最高潮、渐亮+叠化、上下镜头语义相接）；甩切模糊、故障/RGB、闪电叠层、每拍白闪一律不用（v5–v7 用户逐个否决）。
4. **光与粒子**：不加光尘、光斑、耀斑、余烬叠层——原作自带的光就是光。辉光只在源里本来有火/烛的镜头上、强度 ≤0.2（调色级，观众察觉不到“特效”）。
5. **速度与密度**：能量来自**切的密度对比**，不是特效：主歌/桥段/尾声 10–24 cuts/min（留 3–8 s 长镜头），副歌 35–55，终副歌峰值 45–70，峰谷比 ≥2.5–3×（`cutrhythm.py` 检查）。死亡、牺牲、决定性斩击可用 0.6–0.8 慢放（全片 ≤3–4 处，源区间避开切点）；动作顶点不用插帧糊掉线条。
6. **文字**：做歌词就做全（见“全曲歌词字幕”），外加关键台词字幕；全片只用一套克制、一致的字体（明朝/宋体系+细描边或柔阴影），**不用书法/行楷手写体**（用户评价“字体太难看”）；位置固定在下三分之一安全区，不压脸。
7. **声音**：台词必须先做人声分离去BGM（`dialogue_clean.py`，见15-dialogue-isolation.md），放在无人声区或冷开场；**电平校准**：去BGM后的台词有效段(语音帧功率均值)统一到 −17～−19 dBFS，比同时段（已压低的）伴奏高 ≥9 dB；无人声区伴奏压 −12～−20 dB。台词尾音不得越过人声重新进入点——越界就整体前移台词及其口型同步的镜头源时间，不要硬截尾音。音效不要压在台词上。转场合成音效音量比音乐低18–25 dB，宁少勿滥。
8. **片头片尾**：MAD 不是 MV——**默认不放曲名/作品/歌手标题卡**，开头直接进画面，结尾渐黑即可（用户：“我们不是做mv，我们是做mad”）。也不要做“无BGM纯台词冷开场”，除非它明显提升观感。

## 三、工具链（scripts/fxkit/）

- `fx.py`：逐镜头合成器。调色预设(`grades.py`)、亚像素运动(`perspective` 浮点角点+三次插值：推拉/焦点漂移/冲击/落点/震屏/抖动/旋转，采样窗自动钳制)、辉光(RGB)、方向模糊、RGB错位、故障、亮度闪(eq逐帧)、首尾白/黑淡、遮幅(含滑入/滑出)、颗粒、常量/局部慢放；每镜头渲染为精确帧数的中间文件并校验帧数，按内容哈希缓存；`assemble()` 用concat/xfade拼接，再叠加光层(screen)与图形层(alpha)。
- `layers.py`：全长光层(余烬/光尘/光斑/耀斑)与图形层(逐字墨入歌词+译文、对白字幕、手写擦出、标题卡)，均以歌曲时间定位。
- `mix.py`：原曲(只在无人声区压伴奏)+台词片段(高通、淡变)+合成音效(whoosh/impact/riser/reverse/shimmer/puff/glitch/thunder)，输出分轨与混音。
- `cutguard.py`：逐帧切点守卫。
- 依赖：numpy、scipy、Pillow（`requirements-analysis.txt`），人声分离 `demucs`，歌词时间 `mlx-whisper`（Apple Silicon）或 `openai-whisper`。

工作方式：先对3个最复杂镜头做单元测试并看大图 → 960×540预览全片 → 修 → 1080p终渲染 → **终渲染后再做一次全片2 fps条图审看**（本次在终渲染条图上才发现神域白板与白字不可读，预览阶段漏看）。每轮都跑：cutguard、闪烁计数、人声频段对比、台词/音乐电平差(≥8 dB)、textcheck、码率、帧数与时长校验。
- `textcheck.py`：文字可读性红线（见上表）。
- `guard_spec.py build.py [IDs]`：直接对构建脚本里每个镜头的源区间（含变速）跑逐帧切点守卫；每个报警都必须逐帧看图确认（特效/运动的假阳性要写明理由）。
- 高调画面自动换墨色字：`layers.bright_spans()` + `layers.auto_dark()`（按镜头采样字幕区亮度）。
- `lyric_align.py`：用户提供的歌词 → 分离人声强制对齐 → 吸附乐句槽，输出 start,end,ja,zh,align_score,snapped（见“全曲歌词字幕”）。

## 全曲歌词字幕

> **默认：MAD 不加歌词字幕。** agent 不得自行上网抓取、转写或翻译整首受版权保护的歌词（来源在哪都一样），所以只有用户主动粘贴歌词文本时才走下面的流程；用户不提供就整片不放歌词字幕——不要只挑几句做“半套”。


使用歌词字幕时，**每一句唱出的歌词都要有字幕**（不再只挑4–6句锚点；锚点式特效字可以叠加，但底层字幕必须全覆盖）。

1. **文本来源**：歌词原文与译文由用户提供或来自正版/授权来源（歌ネット、J-Lyric、うたてん等，由用户自行复制粘贴）。agent **不得自行复述、补全或改写整首受版权保护的歌词**，也不得把整曲歌词写进项目文件；只可引用用户已给出的短句作锚点。格式：`lyrics.txt` 每行一句日文，可选 `TAB+中文`，或下一行 `zh: 中文`；`#` 注释与空行忽略；副歌重复的句子按出现顺序逐次写出。
2. **乐句槽**：先在分离人声（demucs `vocals.wav`）上做 RMS 包络分段（95分位参考、-12 dB 门限、<0.30 s 间隙合并、>5.5 s 在最深谷切开），得到乐句槽 CSV（start,end）。不信任整曲 whisper 转写的文字。
3. **强制对齐**：`scripts/fxkit/lyric_align.py`（stable-ts `model.align`，失败时退回转写+difflib 读音匹配；需 py3.11/3.12 venv：`stable-ts librosa pykakasi`）。整词全文用 `--mode full`；只有片段/锚点时用 `--mode search` 逐句全曲搜索（先用转写粗定位，再在乐句槽窗口内强制对齐；唱腔拖长的慢歌定位不稳，低分行必须人工听校，结束时间只是估计，不得当终稿）。venv 需含 `stable-ts librosa pykakasi`（large-v3-turbo CPU 约 8 s/秒音频，全曲对齐要数十分钟）。
   `python lyric_align.py --lyrics lyrics.txt --vocals vocals.wav --slots lyrics-timed.csv --out lyrics-aligned.csv`
4. **吸附与清理**：句首/句尾距乐句槽边界 ≤0.35 s 时吸附；时间单调、不重叠；最短显示 1.0 s；与下一句间隙 <0.25 s 时延长到下一句前。
5. **QA**：(a) 无人声时屏幕上不得有歌词（每条字幕的区间内人声 RMS 必须有活动，尾部最多容许 0.3 s 余韵）；(b) 每个乐句槽都被至少一条字幕覆盖，未覆盖的槽要逐个说明（和声/哼唱/拟声）；(c) `align_score` 低于 0.5 的句子逐句复核，必要时手调；(d) 已知锚点误差 ≤0.2 s。

## 冷开场与预合成英雄镜头

- **台词不够就做冷开场**：歌曲人声几乎连续时，在歌前做 20–40 s 的冷开场（纯台词+去BGM人声+极低房间底噪 ≈−50 dBFS+少量字幕），把整片的三条线索先交代清楚，歌曲在“光”上进入。冷开场单独构建（独立工作目录），与主体用 concat demuxer `-c copy` 拼接（断言帧数），音频按采样拼接，并写 `offset.json`；之后 `redline.py --offset S`、`textcheck` 分段跑。
- **英雄镜头走预合成**：`ae.py spec.json out.mp4`（freeze_pop/parallax/depth_dolly/godrays/zoom_through，见16-ae-level-fx.md）渲染成精确帧数的 mp4，构建脚本里镜头源直接写该路径、src=0；`fx.key()` 会把预合成文件的 (size, mtime) 计入缓存键，重渲预合成后镜头自动失效。每个预合成都要看条图：抠像边缘、残影、底边细线。

## 四、参考作品的正确用法

用 yt-dlp 下载参考（仅研究），6 fps 抽帧成表，测切点密度；记录“可观察的技法”和它来自源作品的哪种视觉语言（例：P5R 的勒索信字块、红黑色块、角色登场卡）。迁移的是**原则**：特效语言应从本作品的母题长出来，而不是照搬另一部作品的风格。
